# Проверка мода

1. `.venv\Scripts\python.exe tools\validate.py` после каждой правки (SQL по копиям баз, цвета по ванильным XML, парность en/ru, обязательные тексты лидера, ссылки на LOC). Нужен `OK`.
2. Выбирай проверку по задаче: для данных, фиксируемых при создании партии, нужна новая игра; для дефекта загрузки, производительности, миграции или поведения конкретного сохранения — также соответствующее существующее сохранение. Перезапуск необходим для подхвата новых файлов; не меняй и не удаляй пользовательское сохранение ради диагностики без необходимости. При запросе только на проверку установленной сборки не переустанавливай её автоматически; если подготовить тест уже поручено, установку выполняй сам.
3. Если что-то не работает, сначала сам прочитай доступные логи из `%LOCALAPPDATA%\Firaxis Games\Sid Meier's Civilization VI\Logs\` (`Database.log`, `Modding.log`, `Lua.log`) и ищи `ERROR`. Сверь дату и маркеры с установленной версией: старый лог не подтверждает новый код. Если доступа нет, запроси необходимые логи у пользователя.

## Уроки
- Валидатор ловит не всё. Реальный случай: `INSERT INTO PlayerColors (..., TextColor)` падал в игре (`[ColorManager] ERROR: table PlayerColors has no column named TextColor`), и игра молча брала стандартные цвета. В дампах баз (`reference/game-db`) таблицы цветов нет, валидатор строит её из ванильных XML.
- Базы в `reference/game-db` перезаписываются игрой и могут содержать следы сторонних модов (BBG, Prismatic). Данные дополнений там есть, только если последним загружался набор правил с ними.
- Новый файл вноси в `<Files>` и в действие `.modinfo` вручную (правило в `AGENTS.md`); validate проверит, что файл есть на диске и в списке.
- Сеть ж/д считает Lua (`Lua/RemselysAlexanderII_Railways.lua`): XML-модификаторы читают свойства клетки центра города. Lua валидатором не проверяется, только `Lua.log`.
- Что в игре не проверено, называй «не проверено», а не «работает».
- Указывай отдельно, что существует как прототип, что действительно загружается модом, что проверено вне игры, что установлено и какой сценарий подтвердил пользователь. Проверка старой сборки не подтверждает новую; наличие исходника или успешный тест с заглушками не означают его подключения к игре.
- Игру из Codex запустить нельзя: остановись, скажи, что сделать вручную; логи читай сам. Сборку BLP и установку делай сам (`tools/build.py`, скилл `civ6-mod-build`).

## Почему так
Игра при ошибке данных может молча подставить значения по умолчанию, поэтому общий запуск не доказывает работу конкретной функции. Сопоставляй наблюдение игрока, актуальную сборку, подходящий сценарий и доступные логи; validate отсекает только часть ошибок. Для повторяющегося класса ошибок добавляй проверку в `tools/validate.py`, если она действительно способна его обнаружить.

- Для аудио, арта и анимации валидатор не подтверждает результат в игре. Подбирай проверку воспроизведения, остановки и переходов по изменённому сценарию; подробности маршрутизации — в профильных скиллах. Общее «работает нормально» не означает отдельной проверки всех сцен, языков и платформ.
