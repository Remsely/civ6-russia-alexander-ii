# Нативное накопление дипломатического модификатора

Проверка 20 ноября 2026 относится к установленной `DLC/Expansion2/Binaries/Win64/GameCore_XP2_FinalRelease.dll` с SHA-256 `092abfbb2176f8df04b5212f819dc269dd83aea866ff05aaf489904a1ff7c41f`. Она не описывает автоматически другие версии, платформы и режимы. Для имён использована локальная карта `cru121/civ6-gamecore-reference` на коммите `05e08b4848526f6c47c9996d2649e1fb3edfaf19`; инструкции проверены по DLL.

Ванильный `STANDARD_DIPLOMATIC_CULTURE_BOMBED` задаёт `Accumulates=true` в `Base/Gameplay/Data/Leaders.xml:2697–2716`, а `STANDARD_DIPLOMATIC_CLOSE_TO_VICTORY` задаёт отрицательный `MaxValue` там же около строки 2642. Наличие этих двух возможностей в SQL не доказывает, что их сочетание даст ограниченное линейное накопление.

В этом билде `DiplomacyBaseEffect::Apply` (`0x9446c0`) при флаге накопления считывает текущий показатель, прибавляет `InitialValue`, затем передаёт сумму в `AccumulateExtraValue` (`0x942a40`). Та повторно получает текущий показатель и прибавляет полученное значение. Результат передаётся как начальное и как максимальное значение при активации трекера; настроенный `MaxValue` при этом пути не сохраняется как отдельный предел. `DiplomacyBlackboard::GetDiplomaticModifierFrom` по адресу `0x2bf1f0` вызывается с одинаковыми аргументами пары/типа при всех трёх чтениях в проверенных путях.

`tools/experiments/audit_religion_accumulation.py` исполняет эти инструкции и вспомогательную функцию в Unicorn после проверки SHA. Заглушка возвращает для каждой из трёх одинаковых выборок заданный показатель. Для `InitialValue=-6`, `MaxValue=-54` при включённом `Accumulates` в вызов активации переданы такие пары `(начальное, максимальное)`:

| Текущий показатель | Передано трекеру |
| --- | --- |
| 0 | −6, −6 |
| −6 | −18, −18 |
| −18 | −42, −42 |
| −42 | −90, −90 |
| −75 | −156, −156 |

Контроль без `Accumulates`, при текущем значении 0, передаёт `(−6, −54)`. Среда эмулятора использует x64 Windows ABI, включая положение указателя стека и shadow space; тест проверяет совпадение аргументов выборки, число вызовов и содержимое указателей при вызове активации.

Воспроизведение требует локальную игровую DLL, Python-пакеты `pefile` и `unicorn` и запускается командой `python tools/experiments/audit_religion_accumulation.py --dll <путь к DLL>`. Инструкции не копируются в репозиторий. Эксперимент изолирован: он вручную устанавливает поля объекта эффекта и подменяет чтение текущего значения и вызов активации. Он **не** проверяет чтение значений из SQL, частоту применения эффекта, модификатор `REQUIREMENT_CITY_CONVERTED`, реальные события игры или сохранение. Вывод ограничен поведением этих функций при указанных входах: использовать сочетание `Accumulates=true` и `MaxValue` как доказанный линейный предел −75 нельзя.
