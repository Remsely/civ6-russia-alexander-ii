Рестарт из меню паузы («Начать сначала», `Network.RestartGame`) — 4 ноября 2026. Пользователь: после рестарта вместо нашей речи звучит Пётр. Lua.log той сессии: третья загрузка прошла вовсе без маркеров `REMSELY voice` (ни `hook ready`, ни `dawn values`), при этом ванильные отпечатки построения панели (`true`/`false` — это `trait.InternalOnly` из Civ6Common) и финальный `OnLoadGameViewStateDone` есть — контекст жив, `baseContentReady` выполнился, а наше расширение молча вышло до своих маркеров. Причина: быстрый рестарт не перезагружает FrontEnd (нет AdvancedSetup/JoiningRoom), контекст LoadScreen переиспользуется, а конфигурации игроков движок пересобирает — в момент `LoadScreenContentReady` локальный игрок еще несет дефолтного лидера цивилизации (`LEADER_PETER_GREAT` для России). Ванильный блок при таком лидере проходит все условия: `LoadingInfo` Петра с `PlayDawnOfManAudio=1`, наш патч `bPlayDOM=false` не срабатывает (лидер «не наш»), ставятся свитчи России и играется `Play_DawnOfMan_Speech` = эра + речь Петра; наша проверка `GetLeaderTypeName() ~= LEADER_REMSELY_ALEXANDER_II` молча возвращает управление — без мута, без нашей очереди. Единственный Lua-постер этого события в игре — LoadScreen.lua, других кандидатов нет. Исправление в `RemselysAlexanderII_LoadScreen.lua`: если на content-ready локальный игрок — Россия с Петром, сегмент Петра мьютится немедленно и запускается слежение (`transientWatch`): как только лидер «переворачивается» в Александра, наша речь ставится в очередь от момента ванильного поста (эра успевает прозвучать целиком, Пётр не слышен; переворот после конца эпохи — `STOP_SPEECH_DAWNOFMAN` и наша речь сразу); если лидер остался Петром — за 1,5 с до конца начитки эпохи свитч возвращается на значение России, и настоящий ванильный Пётр звучит как ни в чем не бывало (переворот в этом последнем окне повторно мьютит и ставит очередь); после конца эпохи слежение снимается. Портрет на экране загрузки при рестарте показывает Петра, пока конфиг не обновится, — косметика ванильного движка, общая для всех альтернативных лидеров; панель намеренно не перестраивается: повторный вызов строителя дублирует строки свойств в FeaturesStack.

## Ремонт обеих частей загрузки — 3 ноября 2026

**Коренная причина (найдена третьей итерацией): наша же строка `LoadingInfo` в `Data/GameDefines.sql` изначально несла `PlayDawnOfManAudio = 0`** — с доозвучечных времён мод сам запрещал игре вступление для нашего лидера. Ванильный `bPlayDOM = loadingInfo.PlayDawnOfManAudio` выключался до любых свитчей и хаков, а расширение по тому же флагу возвращало «эры нет, задержка 0» — потому наша речь звучала с первой секунды, а эры не было ни в одной из попыток. Флаг поставлен в 1; он гейтит нативную часть, драйвером которой выступает расширение. Пользователь сообщил: начитка об эпохе («От зарождения жизни в морской глубине…») не играет, звучит только наша речь. Диагноз по банкам: `Play_DawnOfMan_Speech` — одна последовательность из двух switch-контейнеров: группа `Era_DawnOfMan` (9 значений → `DOM_ERA_*` по эпохе) и группа `Leader_Screen_Civilization` (69 значений-цивилизаций → `DOM_LEAD_*`; Россия → `DOM_LEAD_PET`). Прежний `dawnOfManLeaderID = -1` (значение NO_LEADER) глушит всё событие целиком, включая часть об эпохе, — это же подтверждает комментарий ванильного LoadScreen.lua про challenges. Наш лидер без правки тоже не решается в значение России.

Новый порядок (вторая итерация того же дня — вариант с подстановкой индекса Петра в ванильный вызов пользователь проверил, эра всё равно молчала): для Александра `LoadScreen.lua` выставляет `bPlayDOM = false` (как ваниль для resync), и нативное событие целиком запускает наше расширение: свитчи `Leader_Screen_Civilization`/`Civilization` = `DB.MakeHash("Russia")` (это ровно значение 1816587302, лежащее в банке игры; схемы ID совпадают — FNV-1a от имени в нижнем регистре, проверено по Event Id нашего банка), `Era_DawnOfMan` = штатный `UI.GetEraSoundSwitchValue(era.Hash)`, затем `UI.PlaySound("Play_DawnOfMan_Speech")`. Через 0,75 с, пока звучит эпоха, `Leader_Screen_Civilization` переводится на значение `DB.MakeHash("REMSELY_ALEXANDER_II_MUTE")`, которого нет в таблице банка (сегменту Петра нечего играть; спец-значение NO_LEADER не используется — подозрение, что движок при нём глушит всё событие на корню). В момент очереди нашей речи (длина эпохи + 0,5 с) посылается `STOP_SPEECH_DAWNOFMAN` — часть об эпохе уже закончилась, отрезать он может только выживший сегмент Петра. Замеры vgmstream по 11 языкам: у `DOM_LEAD_PET` тишина в начале 0,001–0,79 с, поэтому «остановить позже» не вариант.

Диагностика в Lua.log (маркеры `REMSELY voice:`): `dawn values russia=<...> era=<...> ownLeader=<...> peter=<...>` печатает фактические значения — сверяйте russia с 1816587302 и с peter; если russia отличается, следующий шаг — брать значение из этой строки. ## Сборка

- `tools/build_voice.py` — проверка SHA выбранных WAV, PCM24 → PCM16 48 кГц, банк/метаданные, AST/ANM и регистрация modinfo.
- `tools/voice_animations.ps1` — отдельные FGX речевой длины на основе исходного idle; SDK Granny, без изменения скорости кривых. Перечитывает файл, проверяет Duration, группы/имена дорожек и 121 отсчет каждой кривой; наблюдавшаяся ошибка сравнения 0.
- `tools/build.py` — подготовка речевых FGX, cook BLP обеих платформ, проверка палитр и реальных длительностей таймлайнов.
- `tools/verify_voice.py` — структура банка, медиа/ID, связи сцены, длительности описаний, Volume и ancestry остановки. Штатный validate вызывает проверку банка.

## Маршрутизация и Escape

Банк Wwise v113 содержит только наши шесть PCM-медиа и новые ID. Структура sound берется из локального Speech.bnk Петра; оригинальное игровое аудио не копируется. Встроенные медиа выровнены, DIDX отсортирован, HIRC пишет дочерние объекты перед родителями. InGame UpdateAudio загружает Windows банк через Banks.ini.

Клонируется только нижний actor-mixer; его Parent=оригинальный LeaderSpeech ID 854467727 из Base Speech.bnk. Ванильные объекты не переопределяются. В собственной копии Volume изменен −8 → −7 дБ (+1 дБ); уровни и эффекты общих предков наследуются. Самостоятельный Stop_REMSELY_AlexanderII_Speech целится в наш chain0 и не выключает других лидеров.

Ванильный DiplomacyActionView.CloseFocusedState при Escape в CINEMA_MODE немедленно посылает Stop_Leader_Speech, затем запускает выход из кинорежима; тот же путь используется правой кнопкой мыши. Команда целится в оригинальный LeaderSpeech и достигает нашей ветки по общему предку. Клавиатурное событие поглощает интерфейс дипломатии, поэтому простая подписка стороннего контекста на UserRequestClose не исправляла пропуск приветствия. UI мода дополнительно останавливает свою ветку при смене сообщения, экрана, закрытии и выгрузке контекста.

## Длительности

Для каждого речевого слота согласованы таймлайн, ANM и реальный FGX: время запуска + длина записи + 0,35 с. Обычный idle остается 16-секундным. Речевой clip использует исходные кривые без ускорения, но заканчивается раньше. События одежды/шагов за новым концом удалены. Bind_scene сохраняет изменения при регенерации AST; для удаленного в раннем прототипе FROM_HUMAN восстанавливает штатный старт 0,4 с.

После cooker verify_cooked_timing сверяет реальные Duration таймлайнов BLP обеих платформ с описаниями; Standard_Leader добавляет один пустой таймлайн. Эта проверка не заменяет фактический FGX и игровую проверку.

## Уроки отладки

1. Первый прототип клонировал всех трех предков речи. Голос был слышен, но Escape его не останавливал; собственный stop на следующем сообщении срабатывал. Исправление — общий оригинальный LeaderSpeech как предок.
2. Общий 16-секундный idle задерживал диалог после 6,24-секундного приветствия примерно на 9 секунд. Одна правка Duration в AST не изменила готовый BLP.
3. Отдельный короткий ANM поверх старого 16-секундного FGX изменил таймлайн BLP, но пользователь услышал приветствие 4–5 раз. Исправление — реальные короткие FGX вместе с ANM и таймлайном. Подтверждение пользователя относится к исправленной сборке, а не к неудачной ANM-пробе.
4. Cooker сообщил success при отсутствующих 49 исходных DDS и упаковал ErrorMesh. Проверка палитр выявила дефект до установки; DDS восстановлены только после совпадения дескрипторов TEX с основным checkout. Теперь build предварительно проверяет DDS.
5. Имена событий в BLP не обязаны храниться строками; движок использует хеширование, отличное от Wwise FNV. Поиск строки/FNV в BLP не доказывает наличие или отсутствие речевого триггера.
6. Сравнение только WAV вводит в заблуждение: у Мансы большой gain в банке. По восьми лидерам выбрана умеренная поправка +1 дБ, см. `voice-levels.ru.md`. Пробные +3 дБ не устанавливались.
