# Синхронизация конфигов с Claude Code

Проект ведётся в двух агентах. Конфиги Claude Code — источник истины, конфиги Z Code — их зеркало:

| Claude Code (источник) | Z Code (зеркало) | Правило переноса |
|---|---|---|
| `CLAUDE.md` | `AGENTS.md` | замены окружения: заголовок, вступление, «из Claude Code» → «из Z Code», путь скиллов |
| `.claude/skills/<имя>/` | `.zcode/skills/<имя>/` | точная копия; внутри зеркала скиллы не редактируются |
| `.mcp.json` (`mcpServers`) | `.zcode/config.json` → `mcp.servers` | каноническая схема ZCode: `type` выводится (`command` → stdio, `url` → http), ключи не из схемы отбрасываются — строгий валидатор ZCode молча выкидывает сервер с неизвестным ключом |

Зеркала не правятся руками — правится источник, потом запускается синхронизация. AGENTS.md перегенерируется целиком, ручные правки в нём пропадут.

## Запуск

```
.venv\Scripts\python.exe .agents\skills\claude-config-sync\scripts\sync_claude_configs.py           # синхронизировать
.venv\Scripts\python.exe .agents\skills\claude-config-sync\scripts\sync_claude_configs.py --check   # только проверить расхождения
```

`--check` ничего не пишет и возвращает код 1 при расхождениях — годится как быстрая проверка «разошлись ли конфиги» после правок Claude-конфигов.

## Что скрипт делает и чего не делает

- **Инструкции**: перегенерирует AGENTS.md из CLAUDE.md по таблице замен (список `REPLACEMENTS` в скрипте). Упоминания «Claude Code», не покрытые заменами, перечисляет с номерами строк — реши по смыслу, нужно ли каждое заменить в AGENTS.md (одноразово руками; если контекст устойчивый — добавь шаблон в `REPLACEMENTS`, а не оставляй ручную правку).
- **Скиллы**: копирует и обновляет зеркала; скиллы, которые есть только в `.zcode/skills/` (ZCode-специфичные, как этот), не удаляет — перечисляет, удаление только вручную.
- **MCP**: переписывает `mcp.servers` целиком из `.mcp.json`, сохраняя остальные поля `.zcode/config.json`; об изменениях (добавлен/удалён/отброшен ключ) пишет в отчёт.
- **Не переносится**: allow-list permissions из `.claude/settings.local.json` (у Z Code нет allow-list, режим разрешений выбирается в клиенте) и `enabledMcpjsonServers` (в ZCode серверы подключаются автоматически).

## Правила

- `.zcode/config.json` в `.gitignore` (машинные пути), как и `.mcp.json`; скиллы в обоих `.skills/` и `AGENTS.md` — под git.
- Новые MCP-серверы и правки серверов вноси в `.mcp.json` и синхронизируй, а не правь `.zcode/config.json` напрямую — иначе следующая синхронизация затрёт правку.
- Изменённые MCP-серверы и скиллы подхватываются новой сессией Z Code; текущую перезапусти и проверь Settings → MCP.
- Этот скилл лежит в `.agents/skills/` (не в зеркале), поэтому синхронизация его не трогает.

## Почему так

Ручное зеркалирование однажды забудется, и Z Code начнёт работать по устаревшим инструкциям — расхождение заметно не сразу, а ищется долго. Скрипт делает перенос детерминированным, а спорные места (непокрытые замены, ZCode-_only скиллы, отброшенные ключи) выводит явным списком.
