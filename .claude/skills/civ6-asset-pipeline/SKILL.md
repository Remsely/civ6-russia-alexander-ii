# 3D-ассеты без Asset Editor

Asset Editor хрупкий (падает на импорте FBX-анимации, на русской локали, на чужих путях) и запускается только руками. Поэтому файлы `.fgx` делаем сами, а редактор нужен разве что один раз, чтобы создать новую сущность `.geo`.

## Как устроен 3D-лидер
- `mod/Geometries/<Имя>.geo` + `.fgx` + `.wig` — тело (класс `Leader`); `<Имя>_Camera.geo` — камера: корень и узел `LeaderCamera`, без сетки.
- `mod/Animations/<Имя>.anm` + `.fgx` — анимация; одна может стоять во всех ~28 слотах.
- `mod/Assets/<Имя>.ast` — ассет: DSG `Standard_Leader`, привязки слотов к анимациям, модели и материалы групп треугольников. Собирается скриптом по ассету Петра: `art/3d/test/make_test_ast.py`.
- Подключение в мод (XLP, `Leaders.artdef`, `.dep`, `.modinfo`): `tools/make_leader3d.py` (`--off` — назад к 2D). Сборка — скилл `civ6-mod-build`.
- Образцы: `...\Sid Meier's Civilization VI SDK Assets\Civ6\pantry\` (`Assets/LEAD_RUSS_Peter.ast`, `Geometries/LEAD_RUSS_Peter*`, `Animations/LEAD_RUSS_Peter_*`).

## Сцена лидера (прочитано из LEAD_RUSS_Peter_Camera.fgx)
Сантиметры, Z вверх, лидер смотрит на +X. `LeaderCamera` в (320, 0, 137.741), кватернион (x,y,z,w) = (0.478, 0.478, 0.521, 0.521): смотрит вдоль своей −Z, верх +Y, наклон 4.9° вниз. Импортёр берёт сырые значения FBX и не применяет трансформ корня, поэтому всё запекается в данные.

## Экспорт FBX из Blender (образец — `art/3d/test/export_test_fbx.py`, `export_test_camera.py`)
- Корневой Empty, внутри **рядом** скелет и сетка (сетка внутри арматуры не импортируется). Source Object = корень.
- У каждой сетки материал: группа треугольников = материал, без него сетка пропадает. Триангулировать.
- Данные повернуть и ×100 (`transform_apply`), `apply_scale_options='FBX_SCALE_UNITS'`, `axis_forward='Y'`, `axis_up='Z'`, `bake_space_transform=False`. С `FBX_SCALE_NONE` корень получает масштаб ×100.
- Анимация — отдельный FBX только со скелетом (`*_Anim.fbx`).
- Экспортёр Blender выкидывает постоянные каналы: удерживаемую позу (руки вниз) сделать позой покоя (`armature_apply`), в анимации только движение.
- Blender запускать в фоне: `blender -b art/3d/alexander_assembly.blend --python <скрипт>`; в живом Blender — через MCP (MCP for Blender, пакет `mcp-for-blender` в `.mcp.json`; пользователь нажимает Start MCP Server в N-панели).

## Проверка сцены: числа и кадр игры (после каждого шага сборки)
Не судить по вьюпорту и не показывать пользователю непроверенное:
```
.venv\Scripts\python.exe tools\blend.py audit art\3d\alexander_leader.blend --scene Human [--json out.json] [--full]
.venv\Scripts\python.exe tools\blend.py audit --fbx art\3d\test\LEAD_REMSELY_TEST.fbx
.venv\Scripts\python.exe tools\blend.py render art\3d\alexander_leader.blend --scene Human [--frame N] [--out art\build\x.png]
.venv\Scripts\python.exe tools\blend.py render art\3d\alexander_leader.blend --scene Human --out art\build\v\s.png --views full0,full45,full90,full180,head0,head45,head90,head180
```
Модель смотреть **со всех сторон**, не только с камеры игры: `--views` — ракурсы вокруг модели (`full`/`bust`/`head` + угол: 0 спереди, 90 его левый бок, 180 сзади; `@град` — подъём камеры, например `head0@-20` — снизу на подбородок), плюс общий лист `<out>_sheet.png`.
- `audit` (`tools/blender/audit.py`) — по каждой сетке треугольники, материалы, UV, кости, гистограмма влияний; ошибки: сетка или грани без материала, вершины с >8 костями, вершины без веса, пропавшие текстуры. Код выхода 1 при ошибках. Прогонять и по экспортированному FBX (`--fbx`): это то, что видит импортёр.
- `render` (`tools/blender/render_leader.py`) — кадр с камеры Петра, модель поставлена как при экспорте (поворот +90° по Z, рост `--target-cm`, по умолчанию 150). Пишет, где в кадре макушка и ноги (0 — низ, 1 — верх). Объектив в `.fgx` камеры не хранится: вертикальный угол 19.2° оценён по скриншотам Петра; свет нейтральный, не игровой. Сравнивать кадр с референсом (`art/source/`) и только потом показывать пользователю.
- Оба скрипта ничего не сохраняют в .blend; ~2–3 с каждый (ракурсы — ~1 с на кадр).

## Сборка лидера из исходников
`.venv\Scripts\python.exe art\3d\build_all.py [--from uniform|details|head|pose|regalia|orders|dangles|skin|bake]`, ~6 мин:
- в A-позе MPFB → `alexander_rest.blend`: `build_uniform.py` (MPFB-тело, мундир; из `alexander_assembly.blend`), `build_details.py` (воротник, пуговицы в два ряда, пояс, обшлага, сапоги), `build_head.py`;
- `build_pose.py` → `alexander_leader.blend`: поза портрета (`pose.py`: IK рук и ног, ступни, поворот головы, пальцы; `YAW_DEG` — поворот всей фигуры к камере, только в кадре и экспорте, `sc['pose']`). Детали едут за поверхностью мундира (Surface Deform), пуговицы и пряжка — жёстко; мундир досимулирован тканью на позированном теле (закреплены воротник, плечи, пояс, обшлага, голенища); поза становится позой покоя рига;
- на позированном мундире: `build_regalia.py` (эполеты с двумя рядами канители, Андреевская лента постоянной ширины, аксельбанты), `build_orders.py` (крест на шее, колодка с медалями, звёзды, сабля с темляком; свой атлас `orders_*`), `build_dangles.py` (кости для свободно висящего: темляк, петли аксельбантов, карандаши, бахрома эполет, четыре полы; свойство кости `dangle` = (жёсткость, затухание) пружины; сабля — на своей кости от навершия в кулаке), `build_skin.py` (веса для движения: детали на мундире берут веса сукна под ними, пола над брюками — часть весов брюк (`SKIRT_THIGH`), пояс — жёсткая лента, воротник и горловина без плечевой кости, бахрома едет по рукаву; веки — отдельная сфера под кожей, опускается при моргании; челюсть сглажена по губам; на позу покоя веса не влияют), `build_bake.py` (AO мундира, цвет кистей — один цвет кожи лица, без нарисованных теней). Цвета — как у портрета в итоговом рендере, не в текстуре: кожа лица — портрет со своими морщинами и порами, правленный точечно (`head_touchup.py`: зелень, тени под глазами и на правой стороне, уши, тень под подбородком; заливка кожи одним цветом делала голову пластилиновой), руки — цвет кожи портрета, у сукна и деталей слабый белый блик (`spec` 0.2: при 0.5 красное розовеет), золото ниток светлеет только на гребнях (`THREAD_HI`). Текстуры без пересборки геометрии: `-- textures` у `build_regalia/orders/details.py` (на итоговом файле), `build_bake.py -- skin`, `uniform_paint.py` (на `alexander_rest.blend`), `head_touchup.py` (на `alexander_rest.blend`, из `head_albedo_base.png`), `head_lid.py` (форма левого верхнего века, один раз, оба файла; глаза одного размера с камеры лидера), `python art/3d/head_retexture.py` (новая запечка). Проверка нарисованных теней — `render --flat`. Новая область атласа или UV меняют сетку: тогда `build_all.py --from pose` и сверка вершин.
Что лежит на корпусе (лента, шнуры, ордена, сабля), берёт веса только с корпуса, не с рукавов — иначе в движении рука тянет ленту. `--from details` не идемпотентен (повторно режет штанины) — после правок в uniform/details собирать целиком; `dangles` и `bake` тоже (переносят веса, удаляют подкладку) — после правок в regalia/orders собирать `--from pose`. Шея: поворот головы распределён по высоте шейной трубки (`NECK_TWIST_ZS` в `build_head.py`), борода и челюсть целиком на кости `head` — с весами MPFB граница шла по низу бороды и рвала её; воротник и стойка мундира — на `spine_03` (шея крутится внутри). Регалии кладутся только на внешнюю сторону сукна (слот материала 0): у подкладки нормали внутрь. Карты: albedo, MR (R metal, G roughness), normal (OpenGL; рельеф из картинок и процедурный — канитель, пряди), AO мундира; общий код — `mat_util.py`. Проверка движения: `tools/blend.py render ... --motion test --frames 1,20,42,72,88 --views bust0` (движения в `tools/blender/motion.py`: тело по ключам, висящие детали — пружины, догоняют его с запаздыванием; Взгляд в позе: `build_pose.aim_eyes` наводит глазные яблоки на игровую камеру (`motion.camera`) с поправкой `pose.EYE_OFF`; веки — `LID_DROP` во время симуляции ткани (лицо тела MPFB входит в коллайдер: другие веки — другой мундир на плечах, симуляция хаотична) и `LID_TRIM` после неё. `idle` — петля экрана лидера, 384 кадра (16 с; параметры `IDLE_*`, `LOOK_*`, `BLINK_*`): взгляд в камеру (голова гасит раскачку тела, глаза держат камеру там, где она в глазу в позе покоя, — сами кости глаз в неё не смотрят), дыхание, моргание, переступание вправо и обратно (`IDLE_STEPS`: правая нога, перенос веса, левая приставляется; потом наоборот); ступни (IK с целью, `_plant(..., put=)`) и кисти держатся IK, таз садится настолько, чтобы прямая нога доставала до пола (`_settle`, `REACH`); пола держится от сабли (`LIMBS`); кадр 1 — основная поза; пружины прогоняются дважды, чтобы конец сошёлся с началом; ролик — `render ... --motion idle --movie x.mp4`) и `tools/blend.py clash ... --motion test --frames 20,42,70,88` (сколько треугольников каждой пары объектов пересекается в покое и в кадрах: смотреть, что растёт в движении). Стресс-тесты: `tools/blend.py stress ... --motion stress_<тест> --save x.blend`, потом `render x.blend --frames <кадры> --views ...` — смотреть глазами, цифры только подсказывают где. Висящие детали в движении: гравитация (`HANG`), капсулы бёдер, голеней, плеч и сабли (`LIMBS`), «стенки» того, на чём лежат (`HIT`, можно несколько; стенка движется как кожа поверхности в этой точке — смесь костей с их весами; у предметов, например ножен для темляка, расстояние держится как в покое, у сукна — до `CLEAR`); кисти держатся IK там, где лежат (левая — на эфесе и поворачивается с саблей). Основную позу сверять после каждой правки: координаты всех вершин в покое должны совпасть с прежними (правки весов на позу не влияют).
- Голова (`build_head.py`): голова Hunyuan + шея MPFB сливаются вокселями (`VOXEL` 2 мм) в одну замкнутую сетку, низ бороды и затылок сглаживаются, децимация до `TRIS`, своя UV (smart project), цвет запекается Cycles'ом из источников. Спереди цвет — сам портрет (`head/head_input.png` — фронтальный вид генерации, UV 'proj'), сбоку и сзади — перекрашенная текстура генерации; всё выше глаз, что не смотрит вперёд, — волосы. Не латать шею и текстуру генерации эвристиками: атлас Hunyuan разорван на сотни кусков, в нём запечён свет и синяки. Готовую голову не пересобирать (`build_head.py` неповторяем): форму править `head_mend.py` (опущенная складка над левым веком, отодвинутые губы, расправленные сложенные и пересекающиеся грани; сдвинутым вершинам — веса того места, где они теперь, иначе при повороте головы кожа выворачивается), цвет — `head_touchup.py` поверх `textures/head_albedo_base.png`. После правки формы — стресс-тесты `blink`, `jaw`, `gaze`, `head_turn`, `head_nod`, `head_tilt`, `clash` с `--motion idle` и сверка размера глаз; маски `head_touchup.py` берут место текселя по поверхности: у маленьких островов атласа соседи по атласу — чужие места, размытия по атласу туда не пускать; пятна, натёкшие на соседние острова (низ носа), усреднять в пространстве (`smooth3d`: вокселы по месту текселя на голове), опорой брать кожу в свете, а не всё подряд (иначе среднее — та же нарисованная тень). Осветляя, не обрезать каналы по отдельности: красный упирается в 1 первым, и светлое желтеет и зеленеет (полосы «синяка» под глазами) — делить на наибольший канал.
- Размер головы — таргеты MPFB `head-scale-*` (`HEAD_SCALE` в `build_uniform.py`): у портрета голова 1/7,7 роста, у MPFB 1/8,6.

## FBX → .fgx
```
powershell -STA -ExecutionPolicy Bypass -File tools\fbx_to_fgx.ps1 -Fbx <fbx> -Mode List
powershell -STA -ExecutionPolicy Bypass -File tools\fbx_to_fgx.ps1 -Fbx <fbx> -Mode Geometry -Node <корень> -Out mod\Geometries -Name <Имя>
powershell -STA -ExecutionPolicy Bypass -File tools\fbx_to_fgx.ps1 -Fbx <fbx_Anim> -Mode Animation -Out mod\Animations -Name <Имя>
```
У анимации `-Node` — корневой узел (по умолчанию первый корень), **не** имя дубля: с именем дубля `.fgx` выходит без групп дорожек, и модель в игре стоит неподвижно. Проверка дампом: должна быть строка `trackgroup <корень>: N tracks`. Имя группы = `m_ModelName` тела в `.geo` (у Петра оба `Root`).

Это тот же FBX-импортёр, что вызывает Asset Editor (`Autodesk_FBXInterface`), результат совпадает. `.geo` при этом не меняется: если поменялись имена мешей, групп или костей, `.geo` нужно обновить (Asset Editor → Import или правкой XML по образцу). В `.anm` поправь `m_fDuration`, если сменилась длина.

## Проверка .fgx
`powershell -File tools\dump_fgx.ps1 <прогрев.fgx> <файл.fgx> [-Bones a,b]` — модели, кости (позиция, кватернион, масштаб), дорожки анимации. Первый файл в процессе обёртка не читает — ставь любой прогревочный (например `Animations\LEAD_RUSS_Peter_Neutral_Idle.fgx`). Пути с апострофом («Sid Meier's») не читаются: скопируй файл во временную папку. Тело с сеткой обёртка иногда не открывает (NullReference) — тогда проверяй через FBX в Blender.

## Если всё же нужен Asset Editor
Запуск — из ModBuddy (сам по себе требует аргументы проекта). Падения на старте:
- `ThemeServiceCommands` / `FormatException` — десятичный разделитель Windows запятая; нужна точка (`intl.cpl` → Числа).
- `Logs is invalid` — создать `Documents\My Games\Sid Meier's Civilization VI\Logs`.
- `FbxImporter.dll not found` — рядом с exe нужна копия `FbxImporter_Release.dll` под именем `FbxImporter.dll`.
- Висит после «GameArtSpecificationEditor» — очистить `AutoDocuments` в `%APPDATA%\AssetEditor\1.1\AppSettings.xml` (там несохранённый Untitled).
- Логи: `%APPDATA%\AssetEditor\1.1\Logs\` (свежий по времени); кэш проекта `%APPDATA%\AssetCloud\mod-*-asset-deps.json` можно удалить.
Импорт FBX-анимации в редакторе всегда падает (`ParseWigFiles`) после записи `.fgx` — не используй его, бери `fbx_to_fgx.ps1`. Превью редактора ориентацию показывает не так, как игра; верить игре.

## Симптомы в игре
- Клеопатра вместо лидера — пакет лидера не загрузился (`.dep` без пакетов, нет BLP). Смотри `ArtDef.log`: строка `Loading Package: ...leaders/<пакет>.blp`.
- Чёрный экран, пакет загружен — сначала камера. Камера из нашего FBX (то же положение и кватернион, что у Петра) даёт чёрный экран: `.fgx` Петра из Maya втрое больше, видимо там параметры объектива, которых нет в FBX-экспорте. Поэтому в ассете стоит ванильная `LEAD_RUSS_Peter_Camera` (`make_test_ast.py`, своя — `--our-camera`). Затем модель вне кадра: единицы (метры вместо см), оси (Y вверх), рост. В кадр камеры Петра на x=0 попадает примерно 56..165 см; модель MPFB масштабируется при экспорте до `TARGET_CM` (150, макушка Петра ~158).
- Модель стоит неподвижно — в `.fgx` анимации нет групп дорожек (см. «FBX → .fgx»).
- Бисекция без пересборки: временно направить `Leader_BLP_Entry` в установленном `Leaders.artdef` на ванильный пакет (`ART_LEADER_PETER`, `Leader_Peter.xlp`, `leaders/leader_peter`). Виден Пётр — подключение, свет и UI в порядке, сломан наш пакет. `make_test_ast.py --peter` — наш пакет с телом и анимациями Петра.
