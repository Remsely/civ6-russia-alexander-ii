# Проверка мода

1. `.venv\Scripts\python.exe tools\validate.py` после каждой правки (SQL по копиям баз, цвета по ванильным XML, парность en/ru, обязательные тексты лидера, ссылки на LOC). Нужен `OK`.
2. `tools\install.py`, затем попроси пользователя **перезапустить игру** и начать **новую партию**: цвета, города, повестки и свойства пишутся в сохранение, в старой партии изменений не видно.
3. Если что-то не работает, не гадай: попроси логи из `%LOCALAPPDATA%\Firaxis Games\Sid Meier's Civilization VI\Logs\` (`Database.log`, `Modding.log`, `Lua.log`) и ищи `ERROR`.

## Уроки
- Валидатор ловит не всё. Реальный случай: `INSERT INTO PlayerColors (..., TextColor)` падал в игре (`[ColorManager] ERROR: table PlayerColors has no column named TextColor`), и игра молча брала стандартные цвета. В дампах баз (`reference/game-db`) таблицы цветов нет, валидатор строит её из ванильных XML.
- Базы в `reference/game-db` перезаписываются игрой и могут содержать следы сторонних модов (BBG, Prismatic). Данные дополнений там есть, только если последним загружался набор правил с ними.
- Новый файл вноси в `<Files>` и в действие `.modinfo` вручную (правило в `CLAUDE.md`); validate проверит, что файл есть на диске и в списке.
- Смежность ферм считает Lua (`Lua/RemselysAlexanderII_Farms.lua`): XML-модификаторы читают свойства клетки. Lua валидатором не проверяется, только `Lua.log`.
- Что в игре не проверено, называй «не проверено», а не «работает».
- Игру из Claude Code запустить нельзя: остановись, скажи, что сделать вручную; логи читай сам. Сборку BLP и установку делай сам (`tools/build.py`, скилл `civ6-mod-build`).

## Почему так
Игра при ошибке данных обычно не падает, а молча подставляет значения по умолчанию, поэтому «в игре всё запустилось» ничего не доказывает. Единственные источники правды - логи и проверка в новой партии; validate лишь отсекает очевидное заранее. После каждого найденного класса ошибок добавляй проверку в `tools/validate.py` (так появились проверки цветов и обязательных текстов).
